# Research repo template: doctoral research with agent support

Date: 2026-09-16. Owner: Fabian von Tiedemann. First user: Amanda, doctoral researcher, works with Codex and GitHub. Ambition: a template that more researchers adopt, with a feedback loop back into the template.

## Purpose

A GitHub template repository, `fabian-von-tiedemann/research-repo-template`, public, that a researcher creates their own research repo from and is productive in within an hour. The repo carries a working method, not a subject: questions with an argument chain, trials with measures locked before data, versioned knowledge chains with hashed source excerpts, a decision log, and rules the agent reads at start.

The model is `framtidens-arbetssatt`. Form is taken from it, content is not. Language is English throughout: file names, commands, rules, templates.

## Components

### Knowledge register (`harness/registry.py`)

Copied from the model. Changes:

- Identifiers, error codes and field names stay in English as they already are (`sources`, `claims`, `documents`, `uses`, `depends_on`, `evidence`, `review_status`).
- `CLAIM_TYPES` becomes `{'observation', 'hypothesis', 'interpretation', 'derivation', 'model_result', 'dated_analysis'}`. `dated_legal_analysis`, `requirement_candidate`, `design_hypothesis` go; `interpretation` and `derivation` replace `conditional_derivation`.
- Source kinds (`kind`) documented in `knowledge/README.md`: `literature`, `transcript`, `empirical_report`, `dataset`, `model_trial`, `analysis`, `note`. The rule that an `observation` may only take `supports` from `transcript` or `empirical_report`, and `model_result` only from `model_trial`, stays.
- The optional `legal` block and its validation stay. It costs nothing and a researcher may need it.
- `STATUSES`, `REVIEW_STATUSES`, `SECTIONS`, error codes unchanged.

Commands: `validate`, `index`, `context <ids> [--audience public] [--sources-only]`, `impact [ids] [--as-of]`. Semantics as in the model. Root paths change from `kunskap/` to `knowledge/`.

### Trial engine (`harness/trial.py`)

New, general. A trial is a frozen protocol plus a result plus a separate evaluation.

**Protocol** (`protocol.json`), validated at `create`:

```json
{
  "schema_version": 1,
  "id": "I001-01",
  "investigation": "I001",
  "question": "…",
  "hypothesis": "…",
  "rival": "…",
  "measures": [{"id": "m1", "description": "…", "unit": "…"}],
  "interpretation_rule": {
    "measure": "m1",
    "supports_hypothesis_if": {"op": ">=", "value": 0.7},
    "supports_rival_if": {"op": "<=", "value": 0.4}
  },
  "affects": ["K001"],
  "inputs": ["sources/data.csv"],
  "data_kind": "synthetic",
  "limitations": "…"
}
```

`op` is one of `>=`, `>`, `<=`, `<`, `==`. Values between the thresholds give `undecided`. `affects` are IDs in the register; `create` checks they exist when a register is present. `inputs` are paths relative to the protocol's directory and must stay inside it (`confined`). `data_kind` is `synthetic`, `collected` or `secondary`.

**`create <protocol.json> --out <dir>`**: copies protocol and inputs into `<dir>/`, writes `manifest.json` with `schema_version`, `id`, `created_at`, `hashes` (relative file to SHA256) and `status: "frozen"`. Error if the directory exists.

**`evaluate <dir> [--write]`**: reads `manifest.json`, checks every hash (a changed file is a contract error, exit 2), reads `result.json` that the researcher or a script placed in the directory after freezing: `{"measures": {"m1": 0.82}, "note": "…"}`. Applies the interpretation rule, writes `evaluation.json` with `id`, `evaluated_at`, `measures`, `outcome` (`supports_hypothesis`, `supports_rival`, `undecided`), `rule` (copy), `limitations` (from protocol), `manifest_sha256`. A missing measure is a contract error. A negative or undecided outcome is not a run error (exit 0).

**`demo`**: runs `create` on `investigations/001-example/trial-01/protocol.json` into a temporary directory under `runs/local/`, copies the example's `result.json` in, runs `evaluate --write`, prints the outcome. Output is gitignored.

Exit codes as the model: 0 success, 2 invalid input or contract, 3 incomplete.

### Method (`method/`)

`README.md`: ground rules, field-neutral. Core from the model: blank sheet from the question, rival stated before evidence is gathered, measures and interpretation rule locked before data, evidence grade declared (published before own notes before own experience), red team before synthesis, declared interests (funder, supervisor, own prior position), no changed rule without an entry in `DECISIONS.md`, close-out check. About ten rules. No rule about Digitalist or municipalities.

`templates.md`: template for an investigation README (the question and why, the argument chain, what would change our conclusion, trial table, synthesis), for a trial README (what is tested, protocol, result, assessment, limitations), for a knowledge entry in the register.

`red-team.md`: five lines of attack: convenient conclusion, selection of evidence, measure that does not measure the claim, rival that is a straw man, generalisation beyond the material.

### AGENTS.md and skills

`AGENTS.md`: about twenty lines. Read `method/README.md` before working. Drive the work without permission questions per step but stop at changes of direction. Every close-out runs the close-out check. Never edit a frozen run directory. No paid model calls without explicit instruction. Never put personal data from interviews in the register unless the researcher has decided on de-identification. Example data is never real personal data. At close-out, ask whether the method or the template failed anywhere, and offer to file an issue upstream.

`.agents/skills/new-investigation/SKILL.md`: frontmatter `name`, `description`. Creates `investigations/NNN-<slug>/README.md` from the template, asks the researcher for question, hypothesis, rival and first trial, creates `trial-01/protocol.json`, runs `python3 -m harness validate`.

`.agents/skills/close-out/SKILL.md`: runs the close-out check: write decisions into `DECISIONS.md`, update the investigation README, `python3 -m harness validate`, `python3 -m harness index > knowledge/INDEX.md`, `python3 -m unittest discover -s tests`, check that README reflects the decisions. Then the feedback step: ask whether anything in the method, the templates or the harness got in the way; if yes, draft an issue with the `method-gap` template and offer `gh issue create -R fabian-von-tiedemann/research-repo-template`.

### Feedback loop

The template improves from use. Three mechanisms:

1. `CONTRIBUTING.md`: what to send back (method gaps, template friction, harness bugs, new trial patterns), how (issue on the upstream repo, PR welcome), and what is not wanted (subject content, personal data).
2. Two issue templates in `.github/ISSUE_TEMPLATE/`: `method-gap.md` (which rule or template, what you were doing, what went wrong, what you did instead) and `template-improvement.md`.
3. The close-out skill asks the feedback question every time an investigation closes, so the loop runs without the researcher remembering it.

README has a section "Improving the template" that points to all three.

### Example investigation (`investigations/001-example/`)

A small, field-neutral but real trial that shows the whole loop: question, hypothesis, rival, one measure, one protocol, one input (a small CSV), a `compute.py` that computes the measure and writes `result.json`, and a README that assesses the outcome and records a knowledge entry. The register therefore holds one source (snapshot of the input, `kind: dataset`) and one claim (`K001`, type `derivation`, status `provisional`, `review_status: unreviewed`, with `reconsider_if` pointing at the synthetic data).

Topic: "Does a literature search with two search strings yield a higher share of relevant hits than with one?" The input is a made-up CSV with 40 hits, columns `search_string`, `relevant`. The measure is the share of relevant hits per search string. Data is marked synthetic in the protocol and the README, and the conclusion is written as an example of the form, not as a finding.

Sections: What this is (three sentences). Who it is for and what for (doctoral and master's work; research groups sharing one knowledge state between people and agents; policy analysis where a revised source must trigger re-review; consultancy and product research with declared interests; teaching research method). ## Testing

- `tests/test_registry.py` from the model, with the new `CLAIM_TYPES` and `knowledge/` paths.
- `tests/test_trial.py`: `create` freezes and hashes; a changed file after freezing gives exit 2; `evaluate` gives `supports_hypothesis`, `supports_rival` and `undecided` for three results; missing measure gives contract error; `affects` against unknown ID gives contract error; `demo` passes.
- In a clean clone, `python3 -m unittest discover -s tests`, `python3 -m harness validate` and `python3 -m harness demo` all pass. Standard library only. Python 3.10 or later.

## Delivery

1. Built locally in `~/Developer/forskningsrepo`, committed in steps.
2. `gh repo create fabian-von-tiedemann/research-repo-template --public --source . --push`, then marked as template via `gh api`.
3. `docs/message-to-amanda.md`: a short note in Swedish: what the repo is, how she creates her own from the template, the three commands, that `AGENTS.md` is the first thing Codex reads, and that feedback goes back as issues.

## Out of scope

No model adapter, no sandbox, no queue model, no translation to Swedish. If a researcher later runs language models inside trials, `trial.py` is the interface: a script that writes `result.json` into a frozen directory.
